# Components

This page lists where each component goes, its CSS class names, and how it behaves in mail clients; props and stories are on each component's own page.

| Component             | Purpose                                                                                               | CSS Classes                                                       |
| --------------------- | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |

Variants are named typography presets (font size, weight, line height, color) defined in the theme; their values can change per breakpoint. See [Variants](?path=/docs/docs-theme-and-configuration--docs#variants).

## MjmlMailRoot

Root element for every email template. Renders the full MJML skeleton (`<mjml>`, `<mj-head>`, `<mj-body>`) and provides the theme to all descendant components.

**What it configures from the theme:**

- Body width from `theme.sizes.bodyWidth`
- Body background from `theme.colors.background.body`
- MJML breakpoint from `theme.breakpoints.mobile` (controls when columns stack)
- Base font family from `theme.text.fontFamily`
- Zero default padding on all components
- Renders all registered styles (`registerStyles`) in the `<head>`

Without a `theme` prop, `MjmlMailRoot` uses the default theme, the same as `createTheme()` without arguments.

When to wrap content in `MjmlMailRoot` yourself is described in [Rendering to HTML](?path=/docs/docs-rendering-and-preview--docs#rendering-to-html).

### Contributing to `<MjmlHead>` and `<MjmlAttributes>`

`MjmlMailRoot` accepts `head` and `attributes` slot props for content that can't be expressed via `registerStyles`:

- `head` — use for `<MjmlFont>`, `<MjmlConditionalComment>`, `<MjmlPreview>`, or `<MjmlStyle>` content that depends on React context at render time.
- `attributes` — use for `<MjmlClass>` or per-element defaults (e.g. `<MjmlText fontSize="14px" />`).

Pass the children directly — do not wrap them in another `<MjmlHead>` / `<MjmlAttributes>`:

```tsx
<MjmlMailRoot theme={theme} attributes={<MjmlClass name="link" color="blue" />} head={<MjmlFont name="Foo" href="https://example.com/foo.css" />}>
    {/* email content */}
</MjmlMailRoot>
```

For module-scoped responsive CSS that depends only on the theme, prefer `registerStyles`.

## MjmlSection

Full-width horizontal row with theme integration.

```tsx
<MjmlSection indent>
    <MjmlColumn>
        <MjmlText>Indented content</MjmlText>
    </MjmlColumn>
</MjmlSection>
```

`disableResponsiveBehavior` wraps the columns in an `MjmlGroup`. Every multi-column section needs it, because the group is what makes MJML write the column widths inline — see [Column Widths Must Be Inline](?path=/docs/docs-layout-patterns--docs#column-widths-must-be-inline). A group never stacks by itself: the columns stay side by side on mobile until you add stacking CSS with `registerStyles`.

`slotProps.group` passes props to that `MjmlGroup`, for example `direction="rtl"` to [control the mobile stack order](?path=/docs/docs-layout-patterns--docs#controlling-mobile-stack-order-with-directionrtl):

```tsx
<MjmlSection disableResponsiveBehavior slotProps={{ group: { direction: "rtl" } }}>
    <MjmlColumn width="50%">
        <MjmlText>Right on desktop</MjmlText>
    </MjmlColumn>
    <MjmlColumn width="50%">
        <MjmlText>Left on desktop</MjmlText>
    </MjmlColumn>
</MjmlSection>
```

Indentation values come from `theme.sizes.contentIndentation`, which supports responsive values.

The section takes `theme.colors.background.content` as its background color. Change the default in the theme, or set `backgroundColor` on one section.

**Inside `MjmlWrapper`:** the theme-default `backgroundColor` is suppressed so the wrapper's background shows through. An explicit `backgroundColor` prop still wins.

## MjmlWrapper

Groups multiple `MjmlSection`s that share a background. Must be a direct child of `MjmlBody`; sections go inside.

The wrapper takes the theme's content background by default. Inner `MjmlSection`s suppress their own theme-default background so the wrapper's color shows through; an explicit `backgroundColor` on an inner section still wins.

```tsx
<MjmlWrapper backgroundColor="#dddddd">
    <MjmlSection indent>
        <MjmlColumn>
            <MjmlText>First row</MjmlText>
        </MjmlColumn>
    </MjmlSection>
    <MjmlSection indent>
        <MjmlColumn>
            <MjmlText>Second row</MjmlText>
        </MjmlColumn>
    </MjmlSection>
</MjmlWrapper>
```

Typical uses: multi-section footers with their own color, or grouping sections behind a shared outer padding (e.g., the `direction="rtl"` workaround in [Layout Patterns](?path=/docs/docs-layout-patterns--docs#controlling-mobile-stack-order-with-directionrtl)). The full pattern is in [Grouping Sections with a Shared Background](?path=/docs/docs-layout-patterns--docs#grouping-sections-with-a-shared-background). For a region that also needs different default text color or variants, combine `MjmlWrapper` with a scoped `ThemeProvider` — see [Scoped Theming](?path=/docs/docs-theme-and-configuration--docs#scoped-theming).

## Text Components

### MjmlText

MJML text component — use inside `MjmlColumn` following the standard layout model.

```tsx
<MjmlText variant="heading" bottomSpacing>Large heading with spacing</MjmlText>
<MjmlText variant="body">Regular body text</MjmlText>
<MjmlText>Uses defaultVariant if set in theme</MjmlText>
```

Variant styles merge on top of base theme text styles — properties not set by the variant inherit from the base.

### HtmlText

Themed text for use inside ending tags (`MjmlText`, `MjmlRaw`) or custom HTML structures where MJML components can't be used. Renders a plain HTML element.

```tsx
<MjmlColumn>
    <MjmlRaw>
        <tr>
            <HtmlText variant="body">Themed text in a row of the column's table</HtmlText>
        </tr>
    </MjmlRaw>
</MjmlColumn>

<MjmlText>
    <HtmlText element="div" variant="caption">Rendered as a div</HtmlText>
</MjmlText>
```

### Bottom Spacing

Use `bottomSpacing` to add consistent vertical spacing below text elements:

```tsx
<MjmlText bottomSpacing>First paragraph with spacing below</MjmlText>
<MjmlText bottomSpacing>Second paragraph with spacing below</MjmlText>
<MjmlText>Last paragraph, no extra spacing</MjmlText>
```

The base spacing value comes from `theme.text.bottomSpacing`. Variants can override it individually with their own `bottomSpacing` property (which also supports responsive values).

## HtmlInlineLink

`<a>` element for use inside `MjmlText` or `HtmlText`. Inherits parent's font styles — even on Outlook Desktop, which normally overrides link typography with its own defaults.

Links have no theme configuration of their own. To change their typography, change the styles or variants of the parent text.

```tsx
<MjmlText variant="body">
    Visit our <HtmlInlineLink href="https://example.com">website</HtmlInlineLink> for more.
</MjmlText>
```

### Outlook Workaround

Outlook Desktop ignores `<style>` blocks and applies its own "Hyperlink" style to `<a>` tags, overriding inherited CSS. `HtmlInlineLink` counters this by setting explicit inline styles for font properties (sourced from the parent text component's context). On modern clients, a responsive CSS reset ensures the link adapts when responsive variant overrides apply.

This works only inside `MjmlText` or `HtmlText` with a theme, and only for the properties that the theme or the text's props set. Properties that the theme or the text's props do not set fall back to `inherit`. Classic Outlook ignores `inherit`, and shows the link in its own blue and in Times New Roman.

### Custom Color

Use `!important` when setting a custom link color — the responsive reset uses `inherit !important`, which would otherwise take precedence:

```tsx
<HtmlInlineLink href="https://example.com" style={{ color: "#0066cc !important" }}>
    link text
</HtmlInlineLink>
```

## Image

`MjmlImage` and `HtmlImage` are responsive — the image scales down to fit narrow viewports.

## Divider

Themed horizontal line, styled from `theme.divider` (base styles plus variants). Falls back to a built-in default when no theme is in scope; only `variant` requires a theme.

A dark divider can almost disappear in dark mode, see [Keep a Line Visible](?path=/docs/docs-dark-mode--docs#keep-a-line-visible).

- **`MjmlDivider`** — inside `MjmlColumn`.
- **`HtmlDivider`** — inside ending tags (`MjmlRaw`) or raw HTML.

```tsx
<MjmlDivider variant="thick" />
```

## Button

Themed button, styled from `theme.button` (base styles plus variants). Falls back to a built-in default when no theme is in scope; only `variant` requires a theme.

- **`MjmlButton`** — inside `MjmlColumn`.
- **`HtmlButton`** — inside ending tags (`MjmlRaw`) or any non-MJML context.

`theme.button.padding` is the inner spacing around the label; `MjmlButton`'s `padding` prop is the outer spacing. `fullWidth` makes the button span its container. A gradient `backgroundImage` overlays the solid `backgroundColor`, which stays the fallback for clients that drop `background-image` (Outlook). Outlook ignores `border-radius`, so rounded buttons render with square corners there, see [No CSS `border-radius` in Outlook](?path=/docs/docs-email-client-pitfalls--docs#no-css-border-radius-in-outlook).

```tsx
<MjmlButton variant="primary" fullWidth href="https://example.com">
    Click me
</MjmlButton>
```

For a hand-written full-width button, see [No CSS `box-sizing` in Yahoo Mail](?path=/docs/docs-email-client-pitfalls--docs#no-css-box-sizing-in-yahoo-mail).

## MJML Component Re-exports

`@dextinity/mail-react` re-exports all MJML components, so import every component from `@dextinity/mail-react`.

Common re-exports: `MjmlColumn`, `MjmlSpacer`, `MjmlTable`, `MjmlRaw`, `MjmlGroup`, `MjmlAttributes`, `MjmlAll`, `MjmlClass`, `MjmlStyle`, `MjmlComment`, `MjmlConditionalComment`.

For the full MJML tag reference: https://documentation.mjml.io/
